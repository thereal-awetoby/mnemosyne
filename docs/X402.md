# x402 memory API

Mnemosyne sells one thing to other agents: a check against its private memory
of failures. "Does this situation match something that already went wrong?"
Agents pay per call with [x402](https://docs.x402.org) — no account, no API key.

## What is real and what is mocked

| Part | Status |
|---|---|
| HTTP 402 flow, x402 v2 headers and message shapes | real |
| Payer signs price, recipient, network, endpoint, time window, nonce with an ed25519 NEAR key | real |
| Facilitator checks: signature, payer owns the key, amount, recipient, network, endpoint, time window, single-use nonce, exact accepted terms | real |
| Answer released only after settlement succeeds | real |
| Receipts with request/answer hashes | real |
| **Moving funds from payer to `payTo`** | **mock rail:** recorded in `data/runtime/facilitator-ledger.json`, ids start with `mock_`, every response says `mock: true`. **near-testnet rail:** real wNEAR `ft_transfer` on NEAR testnet (see below) |

`X402_FACILITATOR_URL` selects the HTTP facilitator adapter. It must support
this custom NEAR authorization payload and the same `POST /verify` / `POST /settle`
bodies; a generic EVM facilitator is not a drop-in replacement. The adapter has
only been tested with stubs, not a live NEAR settlement service. The default
demo does not move tokens.

## Two payment rails

`X402_RAIL` picks how `/memory/check` is paid. Routes, receipts, audit, the
private-memory boundary and "answer only after settlement" are identical.

| | `mock` (default) | `near-testnet` (real) |
|---|---|---|
| Scheme | Mnemosyne's own ed25519 authorization | Official x402 NEAR `exact` scheme ([`@x402/near`](https://www.npmjs.com/package/@x402/near) via [`@fastnear/x402`](https://js.fastnear.com/x402)) |
| What the payer signs | price, recipient, endpoint, window, nonce | a NEP-366 delegate action: one `ft_transfer` of the price to `payTo`, 1 yoctoNEAR deposit |
| Asset | "NEAR" (nothing moves) | **wNEAR, `wrap.testnet`** (NEP-141, 24 decimals) |
| Price | 0.001 (accounting only) | 0.001 wNEAR (`X402_PRICE`, smallest units) |
| Verification | our MockFacilitator | the official NEAR verifier: signature, token, recipient, exact amount, 1-yocto deposit, gas cap, expiry, nonce, full-access key, payer balance, `payTo` storage registration |
| Settlement | local ledger, `mock_` ids | relayer submits the delegate on NEAR testnet; id is a real tx hash, receipts link to nearblocks |
| Who pays gas | nobody | the relayer (default: the governor account) |
| Replay protection | single-use nonce in our ledger | NEAR access-key nonce, consumed on chain + in-process settlement cache |
| Interop | Mnemosyne's client | any x402 NEAR client (`createNearPaymentFetch`, browser wallets that sign delegate actions) |

Testnet only: the code refuses `near:mainnet`.

### Run the real rail (testnet, once)

1. `npm run x402:setup -- --new-payer`: registers `payTo` with `wrap.testnet`
   (0.00125 NEAR storage, paid by the relayer), then creates a demo payer
   implicit account, funds it with 0.05 NEAR, registers it and wraps 0.02 NEAR
   into wNEAR (enough for 20 checks). It writes `X402_PAYER_ACCOUNT_ID` /
   `X402_PAYER_PRIVATE_KEY` into `.env` before any money moves. Re-running
   plain `npm run x402:setup` is safe: it skips what's done and tops up the
   payer's wNEAR only when it drops below 0.005.
2. Terminal 1: `set X402_RAIL=near-testnet` (cmd.exe) then `npm run server`.
   The banner says `facilitator: REAL near:testnet`.
3. Terminal 2: `npm run x402:demo:real`. The agent pays with the standard
   x402 NEAR client, prints the settlement tx and a nearblocks link, checks
   the payer lost exactly the price and `payTo` gained it, checks the receipt
   hashes, replays the same payment (refused, not charged again), and ends
   with `REAL DEMO OK`.

The relayer needs a little NEAR for gas: measured 0.000288 NEAR per
settlement on testnet (2026-10-30), plus a temporary prepaid-gas reserve.
The payer needs wNEAR but no NEAR.

## Flow

```
agent                                   Mnemosyne
  POST /memory/check {query}      ->
                                  <-    402 + PAYMENT-REQUIRED (price, payTo, network, endpoint)
  sign authorization with NEAR key
  POST /memory/check {query}
     + PAYMENT-SIGNATURE          ->    facilitator.verify  (all checks; nothing answered if any fail)
                                        memory.check(query)
                                        facilitator.settle  (nonce spent exactly once)
                                  <-    200 {match, citation_id, category, advice, score, receipt_id}
                                        + PAYMENT-RESPONSE (settlement id, payer, amount)
  GET /memory/receipt/:id         ->    proof: payer, amount, settlement id, sha256(request), sha256(answer)
```

All three headers are base64-encoded JSON.

## Messages

`PAYMENT-REQUIRED` (also the 402 body):

```json
{
  "x402Version": 2,
  "error": "payment required",
  "resource": { "url": "http://localhost:8402/memory/check", "description": "...", "mimeType": "application/json" },
  "accepts": [{
    "scheme": "exact",
    "network": "near:testnet",
    "amount": "1000000000000000000000",
    "asset": "NEAR",
    "payTo": "mnemosyne-gov.testnet",
    "maxTimeoutSeconds": 300,
    "extra": { "assetTransferMethod": "mnemosyne-mock-ed25519-authorization", "mock": true, "note": "..." }
  }]
}
```

`PAYMENT-SIGNATURE`:

```json
{
  "x402Version": 2,
  "accepted": { "...": "the accepts[] entry, unchanged" },
  "payload": {
    "authorization": {
      "from": "<payer account>", "to": "mnemosyne-gov.testnet",
      "value": "1000000000000000000000", "asset": "NEAR", "network": "near:testnet",
      "resource": "http://localhost:8402/memory/check",
      "validAfter": 1793386000, "validBefore": 1793386120, "nonce": "<32+ hex chars>"
    },
    "publicKey": "ed25519:...",
    "signature": "ed25519:..."
  }
}
```

The signed bytes are `"mnemosyne-x402-v2:" + canonicalJson(authorization)`
(keys sorted). The domain prefix stops the signature being reused as any other
kind of signed message.

**Payer identity.** For a NEAR implicit account (64 hex chars) the account id
*is* the public key, so the facilitator checks ownership offline. A named
account (`agent.testnet`) is accepted only with `X402_VERIFY_NAMED_PAYERS=1`,
which asks NEAR RPC whether that key exists on that account.

## Refusal reasons (402 `error`)

`payment required`, `invalid_payment_header`, `payment not bound to this resource`,
`invalid_x402_version`, `requirements_mismatch`, `invalid_recipient`,
`invalid_asset`, `invalid_network`, `invalid_amount`, `insufficient_amount`,
`amount_mismatch`, `expired`,
`not_yet_valid`, `time_window_too_long`, `invalid_nonce`, `nonce_already_used`,
`invalid_signature`, `payer_key_mismatch`, `named_payer_unverifiable`.

Amounts must be exact positive decimal integer strings; overpayment, numeric
JSON amounts, hex and exponent notation are refused. A refused payment is not
charged and doesn't spend its nonce, so a payer can fix the problem and retry.
A successful settlement with inconsistent payer, amount, network or mode returns
502 without an answer, rather than asking the client to pay again.

## What leaves the server

| Data | Leaves? |
|---|---|
| citation id, category, one-line `public_summary`, match score | yes, to the payer |
| `keywords`, `private_detail`, other entries | never |
| query text | never stored; receipts keep only its sha256 |

## Routes

| Route | Access |
|---|---|
| `GET /health` | free |
| `POST /memory/check` | x402 |
| `GET /memory/receipt/:id` | free |
| `GET /audit` | free |
| `GET /memory/latest` | free (reads the on-chain head from NEAR) |
| `POST /memory/confess` | `Authorization: Bearer $ADMIN_TOKEN` |
| `POST /cycle/run` | `Authorization: Bearer $ADMIN_TOKEN`; returns public fields only, never the private reasoning |

## Settings (.env)

- `HOST` (`0.0.0.0`) and `PORT` (`8402`). Node.js 22 or newer is required.
- `PUBLIC_URL`: optional pinned public origin, e.g. `https://api.example.com`.
  Set it in production. When unset, the API derives the payment resource from
  the request's `Host` and `X-Forwarded-Proto`; local and reverse-proxy clients
  can use the same server without signing a localhost URL on a public host.
  The proxy must preserve the public Host, set the forwarded protocol, and be
  the only way to reach the server. Do not expose an unprotected origin server.
- `X402_PRICE_YOCTO` (`1000000000000000000000` = 0.001 NEAR).
- `X402_FACILITATOR_URL`, `X402_FACILITATOR_API_KEY`, `X402_VERIFY_NAMED_PAYERS`.
- `ADMIN_TOKEN`: unset disables confess/cycle routes. Use a long random value.
- `DATA_DIR` (`data/runtime`): gitignored, single-process JSON state. New state
  directories/files are owner-only. Back it up; do not share it between workers.
- `MNEMOSYNE_URL` (demo target), `MNEMOSYNE_PAY_TO` (demo recipient allowlist),
  `EXTERNAL_AGENT_SECRET_KEY` (optional demo payer; otherwise a fresh key).

Failed state writes roll back the in-memory change. Corrupt JSON state fails
startup instead of silently resetting spent nonces. Writes are atomic within
one process, not a distributed transaction across a real facilitator and disk.

## Using it from your own agent

```ts
import { postWithPayment } from "./src/x402/client.js";

const r = await postWithPayment("http://localhost:8402/memory/check",
  { query: "about to rotate the signing key on our treasury account" },
  { accountId: "<64-hex implicit account>", secretKey: "ed25519:..." },
  {
    maxAmount: 10n ** 22n,
    allowedPayTo: ["mnemosyne-gov.testnet"],
    allowedNetworks: ["near:testnet"],
  });
// r.body -> { match, citation_id, advice, receipt_id }
```

`postWithPayment` refuses excessive prices, unknown recipients/networks,
unsupported transfer terms, a quoted resource different from the requested URL,
and redirects. A 200 answer must include a settlement proof matching the payer,
amount, network and mock mode. It does not automatically retry a failed payment.

## Verify locally

```sh
npm ci
npm run typecheck
npm test
npm run build
# Terminal 1:
npm run server
# Terminal 2:
npm run x402:demo
```

The tests cover the original payment/replay/privacy cases plus proxy origin
binding, redirect refusal, strict amount parsing, settlement consistency,
failed-write rollback and corrupt-state startup. CI runs these checks and the
mock demo. No test sends a NEAR transaction.
