# x402 memory API

Mnemosyne sells one thing to other agents: a check against its private memory
of failures. "Does this situation match something that already went wrong?"
Agents pay per call with [x402](https://docs.x402.org) — no account, no API key.

## What is real and what is mocked

| Part | Status |
|---|---|
| HTTP 402 flow, x402 v2 headers and message shapes | real |
| Payer signs price, recipient, network, endpoint, time window, nonce with an ed25519 NEAR key | real |
| Facilitator checks: signature, payer owns the key, amount, recipient, network, endpoint, time window, single-use nonce, exact accepted terms | real |
| Answer released only after settlement succeeds | real |
| Receipts with request/answer hashes | real |
| **Moving NEAR from payer to `payTo`** | **mocked**: recorded in `data/runtime/facilitator-ledger.json`, ids start with `mock_`, every response says `mock: true` |

Swap in a real facilitator with `X402_FACILITATOR_URL` (it must speak the same
`POST /verify` and `POST /settle` bodies). The rest of the server doesn't change.

## Flow

```
agent                                   Mnemosyne
  POST /memory/check {query}      ->
                                  <-    402 + PAYMENT-REQUIRED (price, payTo, network, endpoint)
  sign authorization with NEAR key
  POST /memory/check {query}
     + PAYMENT-SIGNATURE          ->    facilitator.verify  (all checks; nothing answered if any fail)
                                        memory.check(query)
                                        facilitator.settle  (nonce spent exactly once)
                                  <-    200 {match, citation_id, category, advice, score, receipt_id}
                                        + PAYMENT-RESPONSE (settlement id, payer, amount)
  GET /memory/receipt/:id         ->    proof: payer, amount, settlement id, sha256(request), sha256(answer)
```

All three headers are base64-encoded JSON.

## Messages

`PAYMENT-REQUIRED` (also the 402 body):

```json
{
  "x402Version": 2,
  "error": "payment required",
  "resource": { "url": "http://localhost:8402/memory/check", "description": "...", "mimeType": "application/json" },
  "accepts": [{
    "scheme": "exact",
    "network": "near:testnet",
    "amount": "1000000000000000000000",
    "asset": "NEAR",
    "payTo": "mnemosyne-gov.testnet",
    "maxTimeoutSeconds": 300,
    "extra": { "assetTransferMethod": "mnemosyne-mock-ed25519-authorization", "mock": true, "note": "..." }
  }]
}
```

`PAYMENT-SIGNATURE`:

```json
{
  "x402Version": 2,
  "accepted": { "...": "the accepts[] entry, unchanged" },
  "payload": {
    "authorization": {
      "from": "<payer account>", "to": "mnemosyne-gov.testnet",
      "value": "1000000000000000000000", "asset": "NEAR", "network": "near:testnet",
      "resource": "http://localhost:8402/memory/check",
      "validAfter": 1793386000, "validBefore": 1793386120, "nonce": "<32+ hex chars>"
    },
    "publicKey": "ed25519:...",
    "signature": "ed25519:..."
  }
}
```

The signed bytes are `"mnemosyne-x402-v2:" + canonicalJson(authorization)`
(keys sorted). The domain prefix stops the signature being reused as any other
kind of signed message.

**Payer identity.** For a NEAR implicit account (64 hex chars) the account id
*is* the public key, so the facilitator checks ownership offline. A named
account (`agent.testnet`) is accepted only with `X402_VERIFY_NAMED_PAYERS=1`,
which asks NEAR RPC whether that key exists on that account.

## Refusal reasons (402 `error`)

`payment required`, `invalid_payment_header`, `payment not bound to this resource`,
`invalid_x402_version`, `requirements_mismatch`, `invalid_recipient`,
`invalid_asset`, `invalid_network`, `insufficient_amount`, `expired`,
`not_yet_valid`, `time_window_too_long`, `invalid_nonce`, `nonce_already_used`,
`invalid_signature`, `payer_key_mismatch`, `named_payer_unverifiable`.

A refused payment is not charged and doesn't spend its nonce, so a payer can fix
the problem and retry.

## What leaves the server

| Data | Leaves? |
|---|---|
| citation id, category, one-line `public_summary`, match score | yes, to the payer |
| `keywords`, `private_detail`, other entries | never |
| query text | never stored; receipts keep only its sha256 |

## Routes

| Route | Access |
|---|---|
| `GET /health` | free |
| `POST /memory/check` | x402 |
| `GET /memory/receipt/:id` | free |
| `GET /audit` | free |
| `GET /memory/latest` | free (reads the on-chain head from NEAR) |
| `POST /memory/confess` | `Authorization: Bearer $ADMIN_TOKEN` |
| `POST /cycle/run` | `Authorization: Bearer $ADMIN_TOKEN`; returns public fields only, never the private reasoning |

## Settings (.env)

`PORT` (8402), `PUBLIC_URL`, `X402_PRICE_YOCTO` (1e21 = 0.001 NEAR),
`X402_FACILITATOR_URL`, `X402_FACILITATOR_API_KEY`, `X402_VERIFY_NAMED_PAYERS`,
`ADMIN_TOKEN`, `DATA_DIR` (`data/runtime`), `EXTERNAL_AGENT_SECRET_KEY` (demo payer).

## Using it from your own agent

```ts
import { postWithPayment } from "./src/x402/client.js";

const r = await postWithPayment("http://localhost:8402/memory/check",
  { query: "about to rotate the signing key on our treasury account" },
  { accountId: "<64-hex implicit account>", secretKey: "ed25519:..." },
  { maxAmount: 10n ** 22n, allowedPayTo: ["mnemosyne-gov.testnet"] });
// r.body -> { match, citation_id, advice, receipt_id }
```

`postWithPayment` refuses to pay more than `maxAmount` or anyone outside `allowedPayTo`.
